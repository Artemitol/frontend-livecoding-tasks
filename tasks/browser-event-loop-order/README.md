# Порядок синхронного кода, microtask и timer callback

**Учебная цель:** Предсказывать порядок синхронного кода, microtask и timer callback в браузерном event loop.

| Метаданные | Значение |
| --- | --- |
| Технологии | JavaScript |
| Тема | Асинхронность |
| Формат | Прогноз вывода |
| Уровень | Средний |
| Время | 12 минут |
| Навыки | Трассировка синхронного стека, очереди microtask, очереди timer callback |
| Предварительные знания | Нет |
| Среда выполнения | Google Chrome 150.0.7871.101, browser main thread, classic script |

<details>
<summary>Теория</summary>

Обычный JavaScript выполняется до конца текущего синхронного стека. После этого браузер исчерпывает очередь microtask, а timer callback с нулевой задержкой становится следующей задачей; ноль не означает немедленный вызов.

</details>

## Условие

Не запускайте код до записи прогноза. Укажите четыре строки в точном порядке и затем объясните причину каждой границы в порядке.

### Входы

Локальный fixture и единственный фрагмент classic script:

```html
<button id="run" type="button">Запустить</button>
<pre id="trace"></pre>
<script>
  const log = (entry) => document.querySelector('#trace').append(`${entry}\n`);
  log('sync:start');
  Promise.resolve().then(() => log('microtask:promise'));
  setTimeout(() => log('timer:0'), 0);
  log('sync:end');
</script>
```

### Выходы

Четыре строки прогноза и объяснение: что завершается до microtask, а что выполняется только после неё.

### Ограничения и побочные эффекты

- Считайте, что код запускается один раз в главном потоке Chrome из classic script.
- Не меняйте `Promise`, `setTimeout` или порядок строк fixture.
- Внешняя сеть, дата и пользовательский ввод не участвуют; ошибочного результата нет.

### Стартовый код

Не требуется: локальный fixture выше является полным предметом разбора.

### Примеры

#### Обычный сценарий

Прогноз: `sync:start`, `sync:end`, `microtask:promise`, `timer:0`. Сначала заканчивается синхронная часть, затем microtask Promise и только потом timer callback.

#### Граничный сценарий

Даже у `setTimeout(..., 0)` callback не вставляется в текущий стек: строка `sync:end` остаётся раньше `timer:0`.

#### Ошибка или пустой результат

Не применимо: fixture не принимает входов и не имеет пустого результата. Ответ без всех четырёх строк считается неполным.

## Критерии готовности

- Указан точный порядок всех четырёх строк.
- Объяснено, почему `microtask:promise` стоит после `sync:end`.
- Объяснено, почему `timer:0` не выполняется синхронно.
- При ручной проверке в Chrome после «Запустить» видны те же четыре строки в том же порядке.

<details>
<summary>Подсказка 1</summary>

Разделите строки на синхронные, microtask и timer callback; сначала расположите только синхронные.

</details>

<details>
<summary>Решение</summary>

### Подход

Полный ожидаемый trace:

```text
sync:start
sync:end
microtask:promise
timer:0
```

`Promise.resolve().then(...)` ставит продолжение в очередь microtask. Она очищается после синхронного кода текущей задачи. `setTimeout` ставит callback в очередь последующей задачи, поэтому он не может обогнать microtask.

### Сложность

- Время: O(1), потому что в fixture фиксированы четыре операции.
- Память: O(1), потому что создаются фиксированные очереди и записи.

### Компромиссы и альтернативы

Запуск fixture подтверждает прогноз в объявленной среде, но не заменяет причинное объяснение. Нельзя переносить этот порядок без оговорок на Node.js, обработчики I/O или другие browser API: в этой задаче рассматриваются только Promise и timer callback в Chrome.

</details>
