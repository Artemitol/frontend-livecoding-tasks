# task-0071 — TDZ и затенение переменной

Песочница для выполнения — [Programiz](https://www.programiz.com/javascript/online-compiler/).

## Условие
```javascript
// Не изменяя код, предскажите три строки вывода: ошибку внутреннего let, затем значения внутреннего и внешнего const.
// Объясните, почему внутренний const не меняет внешнее значение и почему обращение к let до инициализации не читает внешнее имя.

try {
  let x = 4;

  {
    console.log('x:', x);
    let x = 5;
  }
} catch (error) {
  console.log('x error:', error.name);
}

{
  const y = 4;

  {
    const y = 5;
    console.log('y1:', y);
  }

  console.log('y2:', y);
}
```

<details>
<summary>Подсказка 1 — куда смотреть</summary>

Область видимости внутреннего `let` начинается с начала блока, а не со строки инициализации.

</details>

<details>
<summary>Подсказка 2 — с чего начать</summary>

До инициализации внутренняя переменная находится в temporal dead zone, поэтому внешнее значение не подставляется.

</details>

<details>
<summary>Подсказка 3 — почти решение</summary>

Попытка внутри `try` печатает имя `ReferenceError`; внутренний `const y` затем выводит `5`, а после его блока снова читается внешний `y` со значением `4`.

</details>

<details>
<summary>Решение</summary>

```text
x error: ReferenceError
y1: 5
y2: 4
```

Внутренний `let x` затеняет внешнее имя во всём блоке и до инициализации находится в TDZ. Внутренний `const y` существует только в своём блоке, поэтому оба последующих чтения дают сначала `5`, затем внешний `4`.

Ожидаемый результат: `x error: ReferenceError`, затем `y1: 5` и `y2: 4`.

Ручная проверка: сначала запишите прогноз, затем запустите блок и поменяйте внутренний `let` на `var`, чтобы сравнить область видимости.

</details>
