# Взаимоисключающие состояния загрузки

**Учебная цель:** Моделировать взаимоисключающие состояния загрузки через discriminated union.

| Метаданные | Значение |
| --- | --- |
| Технологии | TypeScript |
| Тема | Моделирование типов |
| Формат | Реализация |
| Уровень | Базовый |
| Время | 20 минут |
| Навыки | discriminated union, исчерпывающий switch, readonly-массив |
| Предварительные знания | Базовые union-типы TypeScript |
| Среда выполнения | TypeScript 5.9, strict mode, noEmit, Node.js 26.4.0 |

<details>
<summary>Теория</summary>

Вместо нескольких флагов `isLoading`, `hasError` и `data` можно описать каждый допустимый этап одним полем-дискриминантом `status`. После проверки `status` TypeScript знает, какие поля существуют в конкретной ветви. Присваивание в `never` в недостижимой ветви делает добавление нового статуса заметным во время компиляции.

</details>

## Условие

Реализуйте `getLoadMessage<T>(state: LoadState<T>): string`. Состояние загрузки может быть только одним из четырёх: ожидание, загрузка, успешный ответ с данными или ошибка. Верните русское сообщение для каждого состояния и сохраните проверку исчерпывающей.

### Входы

Один аргумент `state` типа `LoadState<T>`:

- `{ status: 'idle' }`;
- `{ status: 'loading' }`;
- `{ status: 'success', data: readonly T[] }`;
- `{ status: 'error', message: string }`.

### Выходы

- `Ожидание` для `idle`;
- `Загрузка` для `loading`;
- `Загружено: N` для непустого `success`, где `N` — длина `data`;
- `Нет данных` для пустого `success`;
- `Ошибка: message` для `error`.

### Ограничения и побочные эффекты

- Используйте дискриминант `status` и исчерпывающую ветвь с `never`.
- Не моделируйте состояние комбинацией Boolean-флагов и не используйте type assertion.
- Не изменяйте `state` или `data`; не выполняйте I/O и не выбрасывайте исключения.
- Пустой успешный массив — допустимый пустой результат. Комбинация `error` с `data` должна быть ошибкой компиляции.
- Побочные эффекты отсутствуют.

### Стартовый код

```ts
type LoadState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: readonly T[] }
  | { status: 'error'; message: string };

function getLoadMessage<T>(state: LoadState<T>): string {
  switch (state.status) {
    case 'idle':
      return 'Ожидание';
    case 'loading':
      return 'Загрузка';
    // Добавьте ветви success и error, а затем исчерпывающую проверку.
    default:
      return '';
  }
}
```

### Примеры

#### Обычный сценарий

Вход: `{ status: 'success', data: ['a', 'b'] }`.

Результат: `Загружено: 2`, потому что массив содержит два элемента.

#### Граничный сценарий

Вход: `{ status: 'success', data: [] }`.

Результат: `Нет данных`. Пустой массив — корректный успешный ответ, а не ошибка.

#### Ошибка или пустой результат

Вход: `{ status: 'error', message: 'Сеть недоступна' }`.

Результат: `Ошибка: Сеть недоступна`.

Попытка передать `{ status: 'error', message: 'Сеть недоступна', data: [] }` не должна пройти проверку типов.

## Критерии готовности

- Для всех четырёх значений `status` возвращается точное сообщение из условия.
- Непустой и пустой успешные массивы дают соответственно `Загружено: N` и `Нет данных`.
- Ошибочное состояние не может содержать `data`, а функция имеет ветвь, проверяемую через `never`.
- Реализация не мутирует вход, не использует assertion, I/O или исключения.

<summary>Решение</summary>

### Подход

`status` делит union на четыре взаимоисключающие ветви. Длина `readonly`-массива определяет два результата успешного ответа. В `default` переменная типа `never` подтверждает, что все варианты `LoadState<T>` обработаны.

```ts
type LoadState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: readonly T[] }
  | { status: 'error'; message: string };

function getLoadMessage<T>(state: LoadState<T>): string {
  switch (state.status) {
    case 'idle':
      return 'Ожидание';
    case 'loading':
      return 'Загрузка';
    case 'success':
      return state.data.length === 0
        ? 'Нет данных'
        : `Загружено: ${state.data.length}`;
    case 'error':
      return `Ошибка: ${state.message}`;
    default: {
      const exhaustiveState: never = state;
      return exhaustiveState;
    }
  }
}
```

### Сложность

- Время: `O(1)`.
- Память: `O(1)`.

### Компромиссы и альтернативы

Несколько независимых флагов допускают противоречивые сочетания и требуют больше проверок в потребителе. Union с дискриминантом запрещает такие состояния на уровне типов. Проверка `never` не меняет поведение в runtime, но требует обновить `switch`, если в union появится новый статус.

</details>
