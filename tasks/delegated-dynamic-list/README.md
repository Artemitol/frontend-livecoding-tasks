# Удаление динамической строки через делегирование событий

**Учебная цель:** Обрабатывать действия динамически добавленных элементов через делегирование событий.

| Метаданные | Значение |
| --- | --- |
| Технологии | JavaScript, DOM API |
| Тема | DOM-события |
| Формат | Реализация |
| Уровень | Базовый |
| Время | 18 минут |
| Навыки | Всплытие click, поиск целевого action, безопасная проверка DOM-контейнера |
| Предварительные знания | Обработчик click |
| Среда выполнения | Google Chrome 150.0.7871.101, ECMAScript modules, local DOM fixture |

<details>
<summary>Теория</summary>

`click` кнопки всплывает к `ul`. Один обработчик на постоянном контейнере видит и кнопки, добавленные позже. `closest` позволяет найти кнопку действия, а затем принадлежащую ей строку.

</details>

## Условие

Реализуйте один обработчик на `#todos`, который удаляет строку после клика по её кнопке `data-action="remove"`. Не назначайте обработчик каждой новой кнопке.

### Входы

Локальный fixture:

```html
<button id="add" type="button">Добавить строку</button>
<ul id="todos"></ul>
<p id="status"></p>
```

Полный локальный код добавления:

```js
let nextId = 1;
function addTodo() {
  const id = nextId++;
  todos.insertAdjacentHTML('beforeend', `<li data-id="${id}">Задача ${id} <button type="button" data-action="remove">Удалить</button></li>`);
  console.log('[candidate-011] added', { id });
}
```

### Выходы

После удаления показывайте `PASS: динамически добавленная задача <id> удалена делегированным обработчиком.` и пишите ID с числом оставшихся строк в console.

### Ограничения и побочные эффекты

- `#todos` — единственное место назначения обработчика удаления.
- Игнорируйте click, который не пришёл от кнопки удаления внутри `#todos`.
- Мутация разрешена только для DOM списка; внешней сети и ошибок fixture нет.

### Стартовый код

```js
document.querySelector('#add').addEventListener('click', addTodo);
// Один delegated click handler на todos.
```

### Примеры

#### Обычный сценарий

Нажмите «Добавить строку», затем «Удалить» именно у добавленной строки. Она исчезает, а status начинается с `PASS`.

#### Граничный сценарий

Добавьте две строки и удалите вторую: первая остаётся, ID удалённой строки совпадает с кнопкой.

#### Ошибка или пустой результат

Click по пустому месту списка или по элементу без `data-action="remove"` не меняет список и не выдаёт PASS удаления.

## Критерии готовности

- Динамически добавленная кнопка работает без нового listener.
- В списке ровно один listener удаления.
- Нецелевой click безопасно игнорируется.
- В Chrome вручную наблюдаются status PASS и console event удаления.

<details>
<summary>Подсказка 1</summary>

В обработчике списка начните с `event.target.closest('button[data-action="remove"]')`.

</details>

<details>
<summary>Решение</summary>

### Подход

```js
todos.addEventListener('click', (event) => {
  const button = event.target.closest('button[data-action="remove"]');
  if (!button || !todos.contains(button)) return;
  const item = button.closest('li');
  const id = item.dataset.id;
  item.remove();
  status.textContent = `PASS: динамически добавленная задача ${id} удалена делегированным обработчиком.`;
  status.className = 'pass';
  console.log('[candidate-011] removed', { id, remaining: todos.children.length });
});
```

Проверка `todos.contains(button)` не позволяет обработать совпадающий элемент, уже не принадлежащий fixture.

### Сложность

- Время: O(h) на click, где h — число предков до контейнера; для fixture это малая фиксированная глубина.
- Память: O(1), потому что listener один.

### Компромиссы и альтернативы

Отдельный listener на кнопку проще локально, но его приходится назначать каждой новой кнопке. Делегирование требует фильтрации event target, зато устойчиво к динамическому содержимому.

</details>
